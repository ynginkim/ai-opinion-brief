Latent Space, GitHub가 에이전트 시대에 맞춰 다시 짓는 법 (Jay Parikh 인터뷰)

원문 · YouTube 영상 · Latent Space X

한눈에

Latent Space가 Microsoft CoreAI를 이끄는 Jay Parikh와 나눈 대화를 공개했다. GitHub Universe 기조연설을 막 마친 직후다.

GitHub의 다음 확장 과제는 에이전트가 만드는 작업량이다. 이 글은 영상 소개글과 챕터 목록 기준으로 정리했다.

숫자로 보면

GitHub 개발자는 2억 2,500만 명이고, 1년간 커밋이 343억 건이다.

영상에는 ‘새 개발자가 1초에 한 명씩 늘어난다’는 대목이 챕터로 들어 있다.

다루는 주제

Copilot Fusion은 한 작업을 여러 모델에 나눠 품질, 비용, 속도를 높이는 방식이다. 하니스와 모델 라우팅이 함께 좋아지는 과정도 이야기한다.

에이전트에게도 풀 리퀘스트가 필요한지, 저장소에서 ‘코드’는 무엇을 뜻하는지, 대체한 의존성은 누가 관리하는지 같은 질문을 던진다.

한 세션을 폰, 데스크톱, VS Code에서 이어 쓰는 법과 비밀키가 코드에 들어가기 전에 잡는 방법도 나온다.

토큰 예산과 ‘실제로 낸 결과물의 가치’를 어떻게 연결할지도 다룬다.

왜 중요한가

개발 흐름의 중심인 GitHub가 에이전트를 기준으로 구조를 바꾸고 있다는 신호다.

토큰을 많이 쓰는 것과 쓸모 있는 일을 해낸 것을 따로 보려는 흐름도 보인다.

어떻게 바뀌나

Latent Space는 11월 10~12일 샌프란시스코 AI Engineer CODE에서 차세대 코딩 에이전트를 더 다룬다고 안내했다.
