Zechner가 추천한 ‘2026년 10월, 에이전트와 일하는 법’

원문 · X (Mario Zechner) · X 아티클 (Thorsten Ball)

한눈에

코딩 에이전트 pi를 만드는 Mario Zechner가 X에 글 하나를 추천했다. Amp 개발자 Thorsten Ball이 쓴 「How I work with Agents」다. 부제는 ‘2026년 10월 기준’이다.

Zechner의 평은 짧았다. “추천 글. 다 동의하진 않지만 좋은 참고 자료다.”

왜 중요한가

Ball의 글은 요즘 에이전트로 코딩하는 사람의 실제 습관을 정리했다. 핵심만 추리면 이렇다.

  • 최신 모델만 쓴다. 10% 틀리는 모델은 어디가 틀렸는지 몰라서 결국 여러 번 다시 시킨다.
  • ‘어떻게’가 아니라 ‘무엇을’ 말한다. 예: “VM을 2배 빠르게 만들 때까지 멈추지 마.”
  • 개발 전체 흐름을 에이전트가 보게 한다. 로그, 배포, 기능 플래그, 버그 리포트까지 다 보여 준다.
  • 확실한 증거를 요구한다. 데모 영상이나 전후 수치 같은 것이다. Ball은 이게 가장 큰 변화였다고 했다.
  • 같이 고치며 왔다 갔다 하지 않는다. “변형 20개랑 비교 페이지를 만들어”처럼 시킨다.

어떻게 바뀌나

일하는 순서도 바뀐다. 사람이 에이전트를 기다리지 않고, 에이전트가 사람을 기다리게 한다. “2시간 뒤 로그 확인해”처럼 예약 기능을 많이 쓰라고 했다. 컨텍스트 길이도 직접 챙기지 말라고 했다. 요약(compaction)이 잘 돼서다.

리뷰 범위는 확 줄었다. Ball은 핵심 파일 5개 미만과 DB 마이그레이션만 본다고 했다. 변수 이름이나 중복 코드는 이제 신경 쓰지 않는다. 대신 제대로 돌아가는지, 에이전트가 끝까지 테스트했는지를 본다.

Zechner처럼 동의하지 않는 부분이 있는 사람도 많을 것이다. 그래도 지금 현장에서 어떻게 쓰는지 보여 주는 기록으로는 쓸모가 있다.
