Anthropic, 하루 머지 3만 건에 git 대신 Scion으로

원문 · anthropic.com · X @AnthropicAI

한눈에

Anthropic이 사내 버전 관리 시스템 Scion을 직접 만들었다. 5개월 만에 모노레포 전체를 git에서 옮겼다. 하루 머지 건수가 사람용 도구로는 감당이 안 될 만큼 늘어서다.

2026년 5월엔 하루 약 2,500건을 머지했다. 9월엔 하루 3만 건을 넘겼다. Anthropic은 이제 코딩이 아니라 소스 관리·빌드·CI가 병목이라고 했다.

git이 왜 막혔나

main 브랜치 기록만 100GB 가까이 된다. 압축한 작업 사본도 25GB가 넘는다. CI 체크아웃은 하루 2,500만 번 수준이다.

그대로 받으면 하루 600PB가 넘는 git 트래픽이 된다고 계산했다. 한때는 사내 git 미러를 수백 대 돌려 버텼다. 머지가 빨라질수록 이 방식도 운영하기 어려워졌다.

Scion은 어떻게 다르나

출발점은 클라이언트가 거의 다 에이전트와 작업(job)이라는 사실이다. 이들은 늘 온라인이다. 그래서 저장소 전체를 각자 들고 있을 필요가 없다고 봤다.

커밋·머지·리베이스는 서버에서 한다. 클라이언트는 요청한 디렉터리만 받는 sparse 체크아웃이나, 읽을 때 파일을 채우는 가상 체크아웃을 쓴다. 기록과 blame도 API로 물으면 돼서, 로컬 저장소 없이 도는 작업이 많다.

숫자로 보면

Scion 인프라는 예전 git 미러보다 CPU·메모리가 약 200분의 1이다. CI·연구 작업의 체크아웃은 분 단위에서 초 단위로, 100배 가까이 빨라졌다. CI만 보면 CPU 용량 25%를 아꼈다.

Scion과 코드 리뷰 도구 Antique는 7명이 만들었다. 관련 시스템 여섯 개 남짓도 같은 기간에 냈다. 손으로 짠 초기 수집 파이프라인을 내부 Claude Mythos Preview에게 다시 쓰게 했더니, 메모리는 20분의 1, 속도는 4배가 됐다고 한다.

왜 중요한가

에이전트 코딩이 늘면 사람 규모로 짠 개발 인프라가 먼저 막힌다는 실제 사례다. Anthropic은 다른 회사도 6~12개월 안에 비슷한 문제를 겪을 수 있다고 봤다.

어떻게 바뀌나

Anthropic은 Scion이 일반용 git 대체재는 아니라고 선을 그었다. git과 많이 달라서 다른 회사가 그대로 쓰기도 어렵다고 했다. 대신 서버 쪽 API, 필요한 객체만 받는 프로토콜 같은 아이디어를 git에 가져가자고 했다. GitHub·GitLab·오픈소스 커뮤니티와 함께하겠다는 입장이다.

에이전트로 코드를 많이 올리는 팀이라면 체크아웃 시간과 CI 대기부터 재 볼 만하다.
